# 抖音号资料解析与持久化契约

## 字段含义

- `unique_id` 在客户端资料投影中表示对外显示的抖音号，不是登录账号内部 UID，也不是 `sec_uid`。
- 对已经通过 UID / sec_uid 绑定校验的结构化资料，优先采用非空自定义 `unique_id`；缺失时采用有效、非零的 `short_id`。
- `short_id` 只接受有界数字字符串或非负整数表示，拒绝零占位、负数、小数、控制字符及超长值。不以内部 UID 随意补号。
- 快捷登录与扩展导入均通过同一份原生身份校验。原始导入串中的昵称/抖音号只是采集提示，不作为绕过身份校验的依据。

## 保存链路

1. 验证资料与登录凭证属于同一账号。
2. 发布凭证后，`store_imported_profile` 将完整 `VerifiedSelf` 写入资料投影，而不是只写昵称。
3. 持久化时再次核对账号范围与策略归属，跨账号资料拒绝保存。
4. 刷新返回缺失抖音号时，保留同一账号最近一次已验证的抖音号；新返回的有效值正常替换旧值。
5. 本次资料回填走正常 profile-stats 刷新接口，不直接填写猜测号码，不改 Cookie、消息或规则。

## 回归

- `public_handle_uses_short_id_only_when_custom_id_is_missing`
- `public_handle_rejects_invalid_short_ids_and_never_uses_internal_uid`
- `public_handle_missing_refresh_keeps_last_verified_value_across_reopen`
- 账号导入集成场景验证昵称、头像、抖音号和统计字段持久化，以及跨账号错误不改变已保存资料。

## 与采集完整性的边界

登录/发送认证材料完整，与公开账号资料字段齐全是两个独立结论。资料缺失不得被描述为登录认证失败；认证检查通过也不得被描述为所有资料都已采全。
