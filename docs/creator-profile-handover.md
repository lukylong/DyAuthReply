# 创作者平台浏览器会话交接

## 修复对象与证据边界

2026-10-31 实机复现：原生客户端单条发送取得对端同一服务端消息 ID；之后在旧的 Cookie 重建网页发送失败，并观察到登录态失效。该结果确认了失败路径，但尚未单独证明是浏览器存储缺失、并发连接还是平台其他状态导致拒绝。

代码中已确认并修正的缺陷：

- 旧快捷登录清理删除完整 Chromium user-data-dir，旧创作者入口再将 Cookie header 展开成新的 host-only Cookie，丢失原始存储环境。
- 原人工接管仅禁止发送，客户端的 HTTP 收取、WebSocket、资料及历史读取仍可使用同一账号。

暂停入口只是一项止损措施，不能作为功能修复验收。

## 新契约

1. 完整 Chromium 资料保留在原 `quick-auth/sessions/<uuid>` 路径；不得搬移、复制到另一设备或通过 setCookies 重建。
2. 本地绑定包含账号 ID、已校验平台身份、凭证版本和目录 UUID。外部凭证更新使旧绑定失配；不把失配资料当作有效登录。
3. 没有绑定的旧账号仍可打开入口，在新浏览器环境完成一次正常登录。页面身份必须匹配当前账号；不将账号 A 的环境绑定给 B。
4. 浏览器启动前先发布账号人工接管状态，禁止新原生网络请求，等已进入的原生工作退出，并停止及等待 WebSocket owner。其他账号不受影响。
5. 点击结束时先在浏览器内采集当前状态，再关闭并等待浏览器退出，随后导入、验证和恢复原生连接。自动回复保持关闭。
6. 直接关窗时保留完整资料，关闭后验证现有托管凭证；验证失败必须显示待处理，不得显示已恢复发送。
7. 快捷登录确认时先关闭浏览器再发布原生凭证。取消/未完成的临时目录仍可清理，已保留目录不删除。
8. 对待发送任务不得用关闭窗口或登录有效性推断送达。手动发送在人工接管期间立即报告客户端未发送。

## 回归与验收

- 完整资料跨清理保留，路径不变；跨账号、跨身份、跨版本绑定拒绝；目录穿越拒绝。
- 人工接管等待在途原生工作，拒绝新增 HTTP/发送，等待 socket owner 退出。
- 全库 Rust 单元测试、Clippy、Vue 类型检查和本机应用构建。
- 实机验收必须另外记录：首次登录 → 网页单条发送 → 对端相同消息确认 → 结束同步 → 原生单条发送 → 再次打开浏览器仍免扫码。离线测试不代替此项。

## 尚需实机验证的边界

平台登录本身失效、账号验证/验证码、不同 Chromium 版本、Windows 上目录与进程生命周期、客户端异常崩溃恢复，需要分别记录现场结果。本次不把本机构建当作 Windows 或线上验收。

参考：[Chromium user data directory](https://chromium.googlesource.com/chromium/src/+/112.0.5615.165/docs/user_data_dir.md)、[CDP Browser.close](https://chromedevtools.github.io/devtools-protocol/tot/Browser/#method-close)。


## 2026-10-31 实号通道对照与入口修复

同一账号、同一收件人、同一完整浏览器 profile，在原生收发已暂停且只保留一个测试页面时：

- Creator 页面手动发送 C：HTTP 200 / outer 0 / business 8101 / raw_check 1；分配消息 ID，但对端无记录。请求 SDK 0.2.0、app_name douyin_creator、aid 2906，签名字段存在。
- 只切换为官方普通网页，手动发送 D：HTTP 200 / outer 0，无拒绝业务 payload，对端存在同一 server/client message ID 的正文记录。
- 两次 ticket-guard 校验响应头均为 key-sign-result=2、static-sign=1102、static-ts-sign=1102。这几个数值相同，不得单凭它们推断签名失败或造成此次拒绝。
- 原生 B 已由对端及用户确认送达。持久 profile 再次打开无需扫码，结束交接成功。

结论：当前可复现失败被隔离到 Creator 发送通道，不能归结为整个快捷登录环境失效；8101 内部触发规则仍未公开，不能猜成缺少某一个字段。不得将普通 Web 的 query/signing 字段拼接到 Creator 请求以制造所谓修复。

实施：Creator 仅用于已有的身份/登录与结束采集；身份确认后转入从官方 UI 实际取得的普通网页私信地址 `https://www.douyin.com/chat?isPopup=1`，由官方页面自行生成发送请求。入口与提示改为“抖音网页私信”。在自有浏览器进程中关闭上次自动恢复的其他 page targets，保留当前页面和 workers，避免逐次累积后台私信连接。完整 profile 和账号隔离不变。

回归：模拟 CDP 验证身份匹配后才能进入普通网页，身份不符不跳转；不重写 Cookie/UA；只清理同一自有浏览器的其他 page targets。HAR 与对端证据保存在 `.local/creator-profile-fix-20261031/`，不将含账号请求资料的 HAR 加入公开仓库。
