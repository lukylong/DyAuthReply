# 快捷登录与扩展采集延迟

## 2026-10-17 现场与边界

现场快捷登录状态为 `collecting`，仅 `main_uifid=false`；会话、分域 Cookie、账号资料、票据、密钥、设备采样、主站指纹和 SDK Token 均已就绪。一次只读 Cookie 库检查发现 `UIFID_TEMP`，没有正式 `UIFID`。主站页面可显示账号，刷新精选页和另开创作者页后仍缺正式字段。

当时只能确认等待不全是客户端读取延迟，不能据此认定平台封禁、网络原因或账号失效。没有把临时 UIFID 伪装成正式值，没有关闭完整性/同会话校验，没有导入半成品凭证。现场检查未发送消息或修改账号绑定。

### 同日后续：推荐流入口验证通过

在上述同一快捷登录窗口点击“推荐”（`https://www.douyin.com/?recommend=1`），不重新登录、不更改 Cookie，随后原安装客户端报告 `main_uifid=true`、`ready=true`，状态转为 `awaiting_confirmation`，UI 显示“已完成账号校验”。当时等待用户确认，未代点导入。后续只读查询状态变为 `completed`，提示“账号已导入，登录窗口已关闭”，全部完整性字段仍为 true。

据此修正初始化入口：原生不再跳到个人主页，而是推荐流；扩展从创作者页进入时也打开推荐流。如果扩展当前在主站但缺 UIFID，则新建临时推荐页，保留用户原标签页不变，结束后清理临时页。已有正式 UIFID 的主站页可继续复用。扩展源码版本为 2.3.2。

根因属于隐含假设与测试缺口：此前把“任意主站页加载成功”误当作“正式 UIFID 已下发”；提高轮询速度及刷新精选页没有触发正确初始化路径。修复保留正式 UIFID、同会话及配套密钥校验。测试新增导航目标断言、已在主站但缺 UIFID 的初始化、推荐页仍不下发时拒绝不完整采集、原用户标签页保留与临时页清理。现场单账号路径已验证；新构建自动流程及其他账号仍需安装后验收，不据此承诺所有账号都能获取或发送。

## 优化契约

- 原生每轮五个独立 CDP 读取同时发出，按请求编号收集结果，保留分域 Cookie、乱序响应及网络事件处理。批次响应共用 8 秒上限；旧响应、重复响应不作为新结果，指令错误不产出候选凭证。
- 主站初始化前 30 秒，本机采集轮询间隔从 2 秒缩为 500 毫秒，随后恢复 2 秒。登录前、远程身份验证失败、采集出错仍为 2 秒，不提高失败身份校验请求频率。
- 扩展在账号资料请求之前开始加载另一个必要页面；两页初始化并行，保留创作者页面直到完成。读取仅限原 Cookie store；退出时只清理本次新建标签。
- 扩展前 10 秒每 500 毫秒读取一次，之后 1 秒，补采仍有 30 秒期限。已有页面不强制重载。
- 进度显示主站已等待时间与缺失项，30 秒后明确提示检查页面验证/加载错误，不让“正在采集”暗示即将完成。
- 账号、Cookie、密钥、票据一致性和必需字段判定不变；UIFID_TEMP 仍不等同于 UIFID。

## 回归

`collection_pipelines_five_reads_before_waiting_for_responses` 使用本机合成 WebSocket 服务：收到五个读取后才回复，并反序插入网络事件。旧实现超过 1 秒门限，新实现通过。这是确定性的调度/响应关联验证，不是官方网页总耗时测量，也不承诺采集整体提速四倍。

另外覆盖：缺少正式 UIFID、错误/迟到回复、初期快轮询与后期退避、扩展两个入口、资料失败、缺失字段、配套票据与 Cookie store 隔离。推荐流路径的现场结果见上节；真实主站冷启动总耗时须在安装候选版本后另行验收。


## 0.1.43：无名 Cookie 导致整个采集轮次失败

0.1.42 现场再次卡住时，原生 API 报“浏览器Cookie字段无效”，而不是继续缺少 UIFID。只读浏览器 Cookie 元数据确认 www 域存在一个 name 为空、path 为 /、非 HttpOnly 的条目；正式 UIFID 已存在。一次格式错误使 completeness 保留上一轮数据，因此旧灰色标签不能作为实时缺字段的证据。

用户授权只清理该无名条目后，原安装采集器进入 awaiting_confirmation，全部字段为 true，证明根因是无名 Cookie 的兼容性，而非 UIFID 初始化再次失败。未清理其他登录凭证。

修复原生 cookie_header：name/value 必须仍为字符串；空字符串名称仅忽略此条目（与扩展 cookie?.name 过滤一致），非空名称的长度、控制字符和重复会话冲突校验不变。自动采集不修改浏览器存储。回归把无名条目加入完整 CDP fixture，并覆盖异常类型、空值和冲突会话。不存在 .trellis/spec，契约记录于本文。
